# 0002 · 放弃"免解锁降级刷机"路线

- **状态**：已采纳（2026-11-08）· 取代最初的路线假设
- **相关**：`../research/legacy-readme-downgrade-route.md`（原始方案记录）

## 背景

项目最早（11-07）的路线：锁 BL 不能刷 boot，但**能刷索尼签名的官方固件**（`.sin` + `.cms`，与 BL 锁无关）。
所以降到 Dirty COW（CVE-2016-5195）未修复的固件（安全补丁早于 2016-10），再从 shell 提权。

工具链已经打通（`tools/newflasher`，Mach-O arm64 原生），唯一的阻塞项是**固件**：

- 需要 E6653 / SO-01H、构建 `32.1.A.1.163` 一类、补丁 < 2016-10 的 `.ftf`。
- 索尼官方 API（`app.swup.update.sony.net`）只提供当前/最新版本，不提供 2016 存档；
  新接口还要 CDFId + Product Code + 内部 UUID。
- archive.org 无 Z5 条目；2016 年论坛/GDrive/Mega 旧链接全失效。

## 决定

不再寻找老固件，改走**不动固件、直接打内核**的路（R1→R2，最终成功）。
降级路线正式搁置。

## 后果

- ✅ 避开了跨区刷机的副作用（SIM 锁不解除、FeliCa 报废、可能影响信号注册）。
- ✅ 保住了 TA 分区未被刷写（未解锁刷官方固件不影响 TA，相机 DRM 不受损）。
- ⚠️ `tools/newflasher` 与 `tools/libusb-1.0.27` 保留在仓库里——它们是**唯一**的现场恢复候选，
  虽然**从未验证过**（见 ADR 0005）。
- 若日后拿到老固件，这条路仍然完整可用（工具链是好的），只是收益已不如从前
  （已有临时 root）。

## 保留的判断

早期 README 里"大概率只能拿临时 root"的预判被证明是对的——只是原因不同：
不是 verity 开关在 boot.img 里改不了，而是**整条 boot 链都在已签名镜像内**，且 `/system` 另有三堵墙。
