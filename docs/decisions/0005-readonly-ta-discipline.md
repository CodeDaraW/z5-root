# 0005 · TA 研究执行"只读纪律"

- **状态**：已采纳（2026-11-11）
- **相关**：`../research/bl-exploration.md` §11、`../research/bl-conclusions.md` §6.1、§9

## 背景

临时 root 下 TA 块设备 `ro=0`、`blockdev --getro=0`、SELinux Permissive，
用户态 `dd` 整盘可写——能力上"改 TA"是成立的（历史上做过一次单字节写入测试并成功还原）。

但**恢复能力不成立**：

| 恢复入口 | 状态 |
|---|---|
| `fastboot flash` | 被拒（BL 锁） |
| EDL（9008） | 需要**签名** programmer |
| flash mode + newflasher | **从未验证过**（无固件可刷） |

固件自己的失败路径写得很清楚：`Bootconfig parsing failed → 请用刷机工具刷入有效 bootconfig`，
即**停机等人刷机**。而这里没人能刷。

## 决定

1. **默认只读**。一切 TA 分析走 dump + 离线静态分析，或 `tad` 的 open/getsize/read。
2. **任何写入必须先满足三条**：① 用户明确点头；② 有可验证的恢复链；③ 写入前后能在
   同一次开机内做"写 → 读回 → 原样写回自证"。
3. **日志槽（`0x802`–`0x806` 等）不算可写区**：每次开机被设备自己覆盖，写入无法判别持久性。

## 后果

- ✅ 全程零事故。配置区 1962 个 unit 至今与 11-11 的 dump 逐字节相同。
- ⚠️ "全程零写入"这个表述是**不准确的**：11-11 曾在 uid `0x803` 的日志槽做过单字节写入
  （`0x7b001`，`0x22 → 0x31`），读回确认只变 1 字节，随后**已原样还原**（读回摘要与写前一致）。
  正确表述是"**配置区零写入**"。
- 代价：有些问题（例如"改字节后 S1 Boot 是否接受"）永远不会被动态回答。
  但 R6 的结论已让这个实验失去意义——签名真实存在，改了必被拒。

## 被什么推翻

如果出现可用的恢复入口（例如确认 flash mode + newflasher 能刷回官方固件），
这条纪律可以放宽为"有恢复链的受控写入"。
