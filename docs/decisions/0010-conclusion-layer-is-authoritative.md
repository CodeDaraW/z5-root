# 0010 · 文档以"结论层"为权威，过程层只追加

- **状态**：已采纳（2026-11-21，整理仓库时）
- **相关**：`../README.md`、`../timeline.md`

## 背景

这批文档经过 v1→v11 反复修订，同一件事在不同版本里出现过互相矛盾的表述（且**大部分矛盾是真实发生过的自我纠错**）：

- 记录格式读过反（uid/size 在 magic 前还是后）；
- "`mount(2)` 整体被拒"被证伪；
- "三件套只在 fastboot 读"被证伪（开机路径也读）；
- "`0x3E0429B0` 是验签函数"被证伪（是节点表操作）；
- "`0x7b001` 在 uid `0x804`、写的是 `0x30→0x31`"两处都错。

如果直接删改旧段落，就丢掉了"为什么当时这么想"这条最有价值的信息；
如果全部保留而不分层，新读者会被过期结论误导。

## 决定

三层结构：

| 层 | 位置 | 规则 |
|---|---|---|
| **结论层** | `research/bl-conclusions.md`（BL）、`research/root-lpe-attack-surface.md`（提权） | 唯一权威，升版本号，被推翻的结论**保留并加删除线 + 指向新结论** |
| **过程层** | `research/bl-exploration.md`、`bl-review.md`、`history/` | **只追加**，不改写；被推翻的段落标注 `【本节已被 §x 推翻】` |
| **总结层** | `status.md`、`timeline.md`、`pitfalls.md`、`decisions/` | 后写，面向"现在要用"；与长文冲突时以长文的【实测】为准，并回来修正 |

## 后果

- ✅ 新接手者读总结层即可上手，需要取证时能一路追到原始命令与反汇编地址。
- ✅ 自我纠错本身成了资产（`pitfalls.md` 里 26 条大部分来自这些纠错）。
- ⚠️ 维护成本：一次结论变更要动 2~3 个文件。约定是"先改长文并升版本，再同步总结层"。
- ⚠️ 文档之间仍可能残留过期表述。**判定办法**：看该段有没有版本号与【实测/强推断/推测】标记；
  没有标记的段落，默认视为过程记录。
